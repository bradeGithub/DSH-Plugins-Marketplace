## 1. 设置页操作

1. 重启 DSH 后打开 Web GUI，进入 **设置 → DSH 插件市场**
2. 页面自动加载全部插件（已安装置顶，其余按 Star 排序）；点「刷新」强制重新拉取，并以弹窗提示刷新成功/失败
3. 搜索框实时过滤：按插件名 / 仓库全名 / 标签匹配；分类 chips 按栏目筛选
4. 排序/信号过滤：排序下拉支持 **Star 数 / 7 日增速 / 最近更新 / 名称**（7 日增速按 `stars_delta_7d` 排，基线不可得的仓库垫底）；「仅已验证」「隐藏已归档」chips 可叠加过滤
5. 卡片按钮四态：**安装**（实时日志滚动）→ 需要 `API_KEY` 等材料时弹窗索取，填值后点「确认并继续」（留空即跳过该变量）或「取消」中止；**更新**（检测到新版本时出现，`已装 vX → vY` 提示）；**已安装**（灰色锁定）
6. 每个卡片附 GitHub 原仓库链接（新标签页打开）

## 2. 分类体系

构建期按简介/标签自动分类，共 12 类筛选 chips + 卡片分类徽章：

视觉多模态 · 文档办公 · 记忆知识 · 模型用量 · 通知通讯 · 开发编码 · 对话聊天 · 界面美化 · Agent 自动化 · 通用工具 · 聚合资源 · 其他

> 分类只影响市场展示栏目，不影响安装资格。插件作者注意：简介里的宣传性词汇（榜单/公众号收录等）会改变分类判定——见 [STANDARD.md](../STANDARD.md) §6.2。

## 3. 徽章语义

| 徽章 | 含义 | 数据源 |
|---|---|---|
| 社区收录 | 被 awesome 聚合页（默认 [awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin)，社区人工筛选）收录；构建期抓取盖章，悬停可见来源说明 | awesome 列表 |
| ✓ 已验证 | 通过验证层字段契约（`dsh-plugin-verify`）检测 | 验证开放数据层 |
| 披露 ✓ | 作者在 SKILL.md / package.json 声明了披露字段（数据去向/端点/凭据等） | 披露开放数据层（`catalog.json`） |
| 已归档 | GitHub 仓库已归档，仅提示——不改变安装资格 | GitHub 仓库状态 |
| 🛡 | 该 Skills 仓库含安装脚本（执行前有确认门） | 构建期探测 |
| 未验证 | Skills 仓库的 `has_skill` 探测尚未完成（增量续跑补齐） | 构建期探测 |

「社区收录」「披露 ✓」等聚合标记**不等于本市场对插件的质量背书**。

## 4. 通用 Skills 栏目

设置页切到 **通用 Skills** tab：浏览 CI 构建的全量 skills 索引（`agent-skills` ∪ `claude-skills`，20000+ 仓库），支持搜索、触底分页加载、排序/信号过滤（同插件 tab，参数下推服务端、过滤先于分页）、一键安装到 `~/.dsh/skills/`、已安装识别。

## 5. 反馈、环境变量与备份

- **安装反馈**：安装成功入待确认队列，下次打开市场弹「是否正常」（可附备注）；**安装失败**则进度面板就地给「提交反馈」入口（网络类失败主按钮为「重试安装」），关闭面板后弹窗仍兜底。脱敏后经 GitHub token 自动建 issue；无 token 时打开预填链接（body 含有界日志，超长自动降级并把完整快照复制到剪贴板）。偏好三态：每次询问 / 仅失败时询问 / 关闭，弹窗内可「不再询问」。端点契约见 [HTTP-API.md](HTTP-API.md) 反馈节
- **环境变量编辑**：已安装插件的可配置键名查询与写入（只允许写安装时登记过的键名，值不回显）
- **备份/恢复**：安装记录导出、恢复差异预览、WebDAV 推拉（URL 安全规则见 [SECURITY.md](SECURITY.md) §5）
- **目标 profile 切换**：多 profile 环境下切换安装目标（`/api/marketplace/profile`）

## 6. 界面适配

界面与安装日志跟随 DSH 语言设置自动切换中文 / English（设置 → 常规 → Language）；全部样式使用 DSH 主题令牌（`--dsw-alias-*`），自动适配深浅色模式。

## 7. 已知限制（全量）

- **安全模型**：安装端点无用户认证，防护依赖「回环/LAN Host 白名单 + CSRF 头 + Origin 校验 + LAN 写 token」——不要把 DSH web 端口暴露到不可信网络；安装即在本机执行第三方代码，只装信任的仓库（详见 [SECURITY.md](SECURITY.md)）
- 安装任务是单个长 POST（克隆 + 构建 + 材料确认多轮），短超时反向代理可能切断连接——后端仍继续执行，刷新页面确认结果
- 版本检测仅对含 `package.json` 的 cordis 插件生效；skill / 预设 / 脚本类无版本概念；作者发版不 bump `version` 时不提示更新
- 列表多级降级（Contents API → CDN → raw → 内置索引 → 磁盘缓存，详见 [ARCHITECTURE.md](ARCHITECTURE.md) §2）；全部失败才回退 GitHub 搜索 API，未认证限流 **10 次/分**——回退期间频繁点「刷新」可能触发限流（提示刷新失败，稍等再试）；Skills 普通加载走内置索引，`refresh=1` 才拉远端
- **Skills 索引范围**：v1.3 起全量索引（「stars 分段 + 时间窗口二分」突破 1000 条上限）；`has_skill` 探测按 Core API 额度分批补齐，未探测仓库显示「未验证」
- **索引节奏**：每 2 小时增量（最近 3 天 pushed）+ 每天 04:00 UTC 全量重建刷 star 数——新插件最迟 2 小时进索引
- 脚本类插件「已安装」判定基于缓存目录存在性，删除缓存后恢复可安装状态
- 「社区收录」徽章抓取失败时该次构建不更新（增量构建保留旧标，下次构建恢复）
- 安装脚本方式（`irm|iex` / `curl|bash`）的 tarball 无签名校验——该模式的固有限制，细节见 `install.sh` 头部注释
- 插件代码修改后需**重启 DSH** 生效（web profile HMR 禁用）
